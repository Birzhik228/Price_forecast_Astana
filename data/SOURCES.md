# Источники данных

Проверено и скачано **7 октября 2026 года**. Здесь описан неизменённый исходный набор. Очистка, анализ, обучение и приложение уже реализованы; команды запуска и результаты приведены в корневом README. После удаления 459 предполагаемых дубликатов по совокупности признаков осталось **17 929 строк**.

## Основной набор: квартиры Астаны на Kaggle

- Автор: **muraraimbekov**.
- [Astana Real Estate 2025](https://www.kaggle.com/datasets/muraraimbekov/astana-real-estate-2025). Несмотря на название, фактические даты сбора в CSV относятся к январю 2026 года.
- Версия: **4**, обновление на Kaggle — **9 января 2026 года**.
- Лицензия, заявленная автором в [метаданных Kaggle](https://www.kaggle.com/api/v1/datasets/view/muraraimbekov/astana-real-estate-2025): **CC0: Public Domain**.
- [Загрузка закреплённой версии 4](https://www.kaggle.com/api/v1/datasets/download/muraraimbekov/astana-real-estate-2025?datasetVersionNumber=4) проверена без регистрации и API-ключа. Архив содержит `astana_apartments.csv`.
- Локальный файл: `data/raw/kaggle_astana/astana_apartments.csv` — исходные байты CSV, без изменений.
- [Манифест источника](kaggle_astana.source.json) содержит адреса, версию, дату загрузки, SHA-256, размер файла, список колонок и результаты проверки структуры.

Манифест сохранён как запись состояния при скачивании: его примечание о ещё не выполненных очистке и обучении относится к тому моменту. Текущие результаты находятся в `reports/cleaning_report.json` и отчётах обучения.

По фактическому CSV: **18 388 строк, 37 колонок, 7 886 228 байт**, 18 388 уникальных `listing_id`. Во всех строках `source` равен `krisha.kz`. Автор описывает набор как объявления о продаже квартир в Астане. В данных отдельно сохранены шесть районов, включая Сарайшык и Сарыарку.

Поле `parsed_at` охватывает **2026-01-03 — 2026-01-06**. Часовой пояс в значениях не указан: считать их UTC без подтверждения нельзя. Это дата сбора автором; наша дата скачивания её не заменяет.

## Как восстановить исходный CSV

Команды ниже выполняются в PowerShell из корня проекта. Если CSV уже есть, повторно скачивать его не нужно: выполните только проверку SHA-256. Для восстановления используется закреплённая версия **4** из манифеста, а не последняя версия набора.

```powershell
$sourceManifest = Get-Content -LiteralPath .\data\kaggle_astana.source.json -Encoding UTF8 -Raw | ConvertFrom-Json
$sourceCsvPath = $sourceManifest.local_file
if (Test-Path -LiteralPath $sourceCsvPath) {
    throw "Исходный CSV уже существует. Перейдите к проверке SHA-256."
}
$sourceArchivePath = Join-Path ([System.IO.Path]::GetTempPath()) ("astana-v4-{0}.zip" -f [guid]::NewGuid())
Invoke-WebRequest -Uri $sourceManifest.download_url -OutFile $sourceArchivePath -ErrorAction Stop
Expand-Archive -LiteralPath $sourceArchivePath -DestinationPath .\data\raw\kaggle_astana -ErrorAction Stop
```

Результат распаковки: `data/raw/kaggle_astana/astana_apartments.csv`. Архив остаётся во временной папке по пути `$sourceArchivePath`. Команды не используют принудительную перезапись; существующий исходный CSV нужно сохранить.

Проверьте исходные байты до запуска очистки:

```powershell
Get-FileHash -LiteralPath .\data\raw\kaggle_astana\astana_apartments.csv -Algorithm SHA256
```

Значение `Hash` должно совпадать с полем `sha256` в [манифесте](kaggle_astana.source.json), независимо от регистра букв:

```text
923bd5483eaea5fdfe9cbf8d36c40ec1875992f66ed70ee29426dd6bc2d189ee
```

Если значение отличается, не используйте файл для воспроизведения результатов: проверьте версию архива и повторите загрузку в отдельную папку. Не открывайте и не пересохраняйте исходник в редакторе таблиц перед проверкой.

## Соответствие признаков проекту

| В проекте | Колонка в скачанном CSV |
| --- | --- |
| Целевая цена в тенге | `price_local` |
| Площадь | `area` |
| Комнаты | `rooms` |
| Этаж | `floor` |
| Этажность | `total_floors` |
| Год постройки | `year_built` |
| Тип дома | `house_type` |
| Состояние | `condition` |
| Район | `district` |
| ЖК | `residential_complex_name` |
| Ссылка | `url` |
| Дата сбора | `parsed_at` |

Описание на Kaggle упоминает `price_kzt`, но **такой колонки в скачанной версии нет**: фактически она называется `price_local`. Есть отдельная цена `price_usd`; медианное отношение `price_local / price_usd` в файле — около 508,913, что согласуется с валютами, указанными автором.

`price_per_m2` в этом CSV соответствует приблизительно `price_usd / area`, то есть это цена за м² в долларах. Не следует принимать её за тенге. При очистке **исключены и `price_usd`, и `price_per_m2`**; в признаки модели они не входят, поскольку содержат информацию о целевой цене и вызвали бы утечку. Приложение рассчитывает цену за м² из прогноза полной цены в тенге и введённой площади.

## Проверенные ограничения

| Нужный признак | Пустых значений |
| --- | ---: |
| `price_local`, `area`, `rooms`, `year_built` | По 0 |
| `floor` | 971 |
| `total_floors` | 971 |
| `district` | 778 |
| `house_type` | 1 117 |
| `condition` | 10 887 (59,2%) |

Таблица показывает пропуски в исходных 18 388 строках, а не в очищенной выборке. Это проверка наличия значений, а не подтверждение их корректности. В описании автор заявляет предварительное удаление дубликатов и некоторых выбросов. Наша очистка дополнительно исключила 459 предполагаемых дубликатов по совокупности признаков и сохранила их отдельно в `data/processed/listings_rejected.csv`; это не доказательство, что все такие объявления относятся к одной и той же квартире. Дубликатов по ссылке и строк вне заданных порогов цены и площади не обнаружено. Подробный отчёт находится в `reports/cleaning_report.json`. Фактический диапазон `price_local` — от 3 990 000 до 1 500 000 000 ₸ — отличается от диапазона в описании Kaggle.

Большое число пропусков состояния ограничивает, насколько уверенно модель учитывает ремонт: в очищенной выборке их **10 498 (58,55%)**. Цены отражают предложения января 2026 года, а не текущие сделки. Набор использован для учебного обучения модели; актуальность будущих прогнозов потребует отдельной проверки на более свежих данных.

## Проверенные альтернативы на Kaggle и GitHub

1. **Turarr — Astana Real Estate Dataset:** [Kaggle](https://www.kaggle.com/datasets/turarr/astana-real-estate-dataset), [GitHub](https://github.com/Turarr/Krisha.kz-Astana-Real-Estate-Dataset). Реально доступны сырой `krisha_data_raw.csv` и подготовленный `astana_real_estate_dataset.csv`, по 5 003 строки. На Kaggle заявлена CC0, версия опубликована 30 марта 2026 года. В GitHub отдельная лицензия не обнаружена. В авторском ноутбуке подготовки Сарайшык ошибочно заменяется на Сарыаркинский район; это подтверждается объединением 511 и 508 строк в 1 019 строк готового набора. Также пропуски заранее заполнены по всему датасету. Поэтому готовый вариант не выбран основным, несмотря на более свежую дату. Kaggle и GitHub здесь — связанные публикации, а не независимые выборки для объединения.
2. **zhanarbakenova — astana-estate-krisha-kz:** [Kaggle](https://www.kaggle.com/datasets/zhanarbakenova/astana-estate-krisha-kz). Метаданные подтверждают публикацию 23 апреля 2024 года, Apache 2.0 и CSV-файлы, включая `data/krisha_df_rought.csv`. Содержимое полностью не проверялось; резервный вариант старше выбранного набора.

Другой город для продолжения проекта не нужен: подходящие данные именно по Астане найдены. На этапе 3 скачанный оригинал использован без перезаписи; результат очистки сохранён отдельно в `data/processed/listings_clean.csv`.
