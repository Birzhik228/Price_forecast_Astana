# Прогноз цен на квартиры в Астане

Учебный ML-проект: от сбора объявлений о продаже квартир в Астане до веб-приложения на Streamlit. Пользователь вводит параметры квартиры и получает прогноз полной цены в тенге.

**Все семь этапов завершены.** Форма Streamlit принимает восемь параметров квартиры и показывает прогноз цены, цену за м² и ориентировочный диапазон ±MAE. Используется RandomForest: test MAE ≈ 7,69 млн ₸, RMSE ≈ 14,79 млн ₸, R² ≈ 0,842. Доступны [таблица моделей](reports/model_comparison.csv), [ноутбук EDA](notebooks/01_eda.ipynb) и [HTML-отчёт EDA](reports/eda_report.html). Это законченный учебный проект на данных января 2026 года; качество на текущем рынке ещё не проверено.

## Быстрый запуск готового приложения

В текущей рабочей папке окружение и модель уже созданы. Откройте терминал **в корне проекта**, где лежит `app.py`, и выполните:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Откройте [http://127.0.0.1:8501](http://127.0.0.1:8501). Терминал должен оставаться открытым; **Ctrl+C** останавливает сервер. После перезагрузки компьютера или остановки сервера команду нужно выполнить снова. Установка на другой компьютер и восстановление данных описаны ниже; клонирование Git само по себе не переносит модель и CSV.

## Что делает приложение

Входные параметры:

- район;
- площадь, м²;
- количество комнат;
- этаж и этажность дома;
- год постройки;
- тип дома;
- состояние квартиры.

Результат: прогноз цены в ₸, рассчитанная из него цена за м² и ориентировочный диапазон на основе MAE — средней абсолютной ошибки модели. Такой диапазон не является гарантированным доверительным интервалом.

Модель оценивает **цену предложения из объявления**, а не фактическую цену сделки. Название ЖК, адрес, ссылка и дата сбора сохраняются для контроля качества данных, но не входят в восемь признаков модели.

## Стек

- `requests` и `BeautifulSoup` — загрузка и разбор HTML.

- `Streamlit` — веб-интерфейс на Python.

Streamlit объединяет форму и вызов Python-модели без отдельного фронтенда. Отдельный FastAPI-сервис не реализован; его можно добавить, если потребуется API для другого интерфейса.

4. Изучите [готовый HTML-анализ](reports/eda_report.html) или повторно выполните ноутбук:


5. Обучите модели и сохраните лучший пайплайн:

   ```powershell
   .\.venv\Scripts\python.exe -X utf8 train.py
   ```

6. Запустите приложение:


Для готового приложения без переобучения перенесите код, конфигурацию и **оба** файла из одного запуска: `models/best_model.joblib` и `models/model_metadata.json`. Рабочая модель занимает около 81 МБ; она и CSV исключены из Git. Папку `.venv` между компьютерами не переносите — создайте окружение заново. При новом датасете повторно создайте EDA/отчёты и обновите указание периода данных в приложении; сохранённые старые метрики не описывают новую модель.

## Воспроизводимость

- Общий `RANDOM_STATE = 42` задан в `config.py` и передаётся в разбиение, cross-validation, подбор параметров и модели, где этот параметр поддерживается.
- Доля тестовой выборки задана как `TEST_SIZE = 0.2` — разбиение 80/20. Индексы строк и CV-fold сохраняются в `reports/split_manifest.csv`.
- Пути строятся через `pathlib` относительно файла `config.py`, а не текущей папки терминала. Пути с именем пользователя не зашиты в код.
- Версии прямых зависимостей закреплены в `requirements.txt`. Полный снимок **121 установленного пакета** после создания приложения сохранён в `requirements.lock.txt` для Windows / Python 3.12.14. Это список точных версий, без хешей пакетов и без гарантии переносимости на другую ОС.
- `reports/training_environment.txt` описывает окружение **в момент обучения**, до установки Streamlit. Установка интерфейса добавила пакеты и изменила версии Pillow/packaging; версии ML-библиотек сохранились. Оба файла имеют разное назначение и не подменяют друг друга.
- Сведения о Python, версиях ML-библиотек, признаках и SHA256 модели сохранены в `models/model_metadata.json`. SHA256 исходного и очищенного CSV — в `reports/cleaning_report.json`. Для воспроизведения нужны тот же CSV и порядок строк; один `random_state` не гарантирует одинаковый результат на другой выборке или ОС.

## Этап 2: парсер

Для дальнейших этапов уже доступен готовый датасет Астаны с Kaggle, поэтому запуск парсера сейчас не требуется. Описание ниже относится к самостоятельному сбору. Схема внешнего CSV отличается от схемы нашего парсера: `clean.py` явно сопоставляет колонки обоих форматов. Не используйте скачанный CSV как `--output` парсера.

### Перед запуском

Проверьте актуальные [robots.txt](https://krisha.kz/robots.txt) и [пользовательское соглашение](https://krisha.kz/content/special/agreement). На 07.10.2026 пункт 5.3 соглашения требует письменного разрешения Kolesa на автоматический доступ и извлечение объявлений. Отсутствие запрета пути в robots.txt не заменяет такое разрешение. Команды сбора ниже предназначены для использования после получения необходимого разрешения и проверки действующих правил. Скрипт печатает напоминание при запуске, но автоматически условия не проверяет.

При разработке получены только HTML каталога и одной карточки для изучения разметки. Датасет не собирался. Если получить разрешение не удастся, можно использовать предоставленный CSV или другой разрешённый источник; вымышленные объявления не будут заменять реальные данные.

### Установка и автономная проверка

Если `.venv` уже создано, для этапа 2 достаточно установить две зависимости:

```powershell
.\.venv\Scripts\python.exe -m pip install requests==2.32.5 beautifulsoup4==4.13.5
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -p test_scraper.py -v
.\.venv\Scripts\python.exe -X utf8 scraper.py --help
```

Тесты не обращаются к сайту и не создают учебный датасет. Они используют сокращённые фрагменты реального HTML и временные файлы. Проверяются извлечение полей, пропуски, докачка, лимиты, ошибки сети и остановка при ограничении доступа. В Linux/macOS замените `.\.venv\Scripts\python.exe` на `.venv/bin/python`.

### Ограниченный запуск

После проверки правил и получения разрешения начните с одной страницы и не более трёх новых объявлений:

```powershell
.\.venv\Scripts\python.exe -X utf8 scraper.py --max-pages 1 --max-listings 3
```

Без параметров предел — одна страница каталога, но с загрузкой всех ещё не сохранённых карточек этой страницы. Лимит страниц не равен числу HTTP-запросов: на каждую новую карточку нужен отдельный запрос за подробностями.

Повторный запуск продолжает заполнение того же CSV, пропуская сохранённые ссылки:

```powershell
.\.venv\Scripts\python.exe -X utf8 scraper.py --max-pages 3
```

Дополнительные параметры:

| Параметр | Значение |
| --- | --- |
| `--max-pages N` | Максимум страниц каталога за запуск, по умолчанию 1 |
| `--max-listings N` | Максимум **новых сохранённых** объявлений за запуск |
| `--start-page N` | Начальная страница, по умолчанию 1 |
| `--output PATH` | CSV; по умолчанию `data/raw/listings.csv`, относительный путь считается от корня проекта |

Для повторения пропущенных из-за ошибок карточек снова запускайте с первой страницы. `--start-page` полезен для ручного продолжения большого обхода, но выдача меняется со временем: положение объявления на странице не постоянно. Докачка ориентируется на ссылки, а не на номера строк или страниц. Для нового снимка рынка используйте другой `--output`: уже записанные цены автоматически не обновляются.

### Формат данных

CSV записывается в UTF-8 с BOM, разделитель — запятая. Числа на этапе сбора остаются строками: например, `price` содержит `66 500 000 ₸`. Их преобразование выполняет `clean.py` на этапе 3.

| Колонка | Содержание |
| --- | --- |
| `price` | Полная цена предложения в тенге, в формате сайта |
| `area` | Общая площадь в м², без единицы измерения |
| `rooms` | Количество комнат |
| `floor` | Этаж квартиры |
| `total_floors` | Этажность дома |
| `year_built` | Год постройки, если указан |
| `building_type` | Тип дома |
| `condition` | Состояние квартиры |
| `district` | Район без суффикса «р-н» / «район», если указан |
| `residential_complex` | Название ЖК, если указано |
| `url` | Каноническая ссылка на объявление без рекламных меток |
| `collected_at` | Момент сбора в ISO 8601, UTC (`+00:00`), не дата публикации |

Пустые необязательные поля сохраняются пустыми; они не заменяются нулями или догадками. Если не удаётся подтвердить продажу квартиры в Астане или извлечь цену, площадь и комнаты, парсер останавливается с диагностикой для проверки разметки. Телефоны, имена продавцов и фотографии не собираются.

### Как устроены запросы и докачка

- Все CSS-селекторы вынесены в `SELECTORS` в начале `scraper.py`. Они проверены на HTML от 07.10.2026; источники фрагментов указаны в `tests/fixtures/README.md`. Это проверка конкретного образца, а не гарантия для всех вариантов страницы.
- `requests.Session` использует собственный User-Agent `AstanaApartmentResearch/0.1 (educational project)`. Запросы последовательные, с паузой 1–2 секунды перед каждым, включая повторы.
- Таймаут запроса — 30 секунд. Сетевые ошибки и HTTP 5xx повторяются до трёх попыток с дополнительными паузами 2 и 4 секунды.
- HTTP 401/403/429, перенаправления и распознанная CAPTCHA останавливают сбор. Автоматического обхода ограничений нет. При 429 значение `Retry-After` выводится в журнал для ручного решения о следующем запуске.
- Ошибка загрузки отдельной карточки, например 404 или исчерпанные повторы, записывается в журнал; следующая карточка обрабатывается дальше. Неудачная ссылка не считается сохранённой. Ошибка страницы каталога или неожиданная разметка останавливает обход.
- Каждая строка сразу дописывается, сбрасывается из буфера и синхронизируется с диском (`flush` + `fsync`). При Ctrl+C предыдущие строки остаются в файле. Перед докачкой проверяются заголовок и структура существующего CSV; повреждённый файл не перезаписывается. После аварийного отключения может потребоваться вручную проверить последнюю незавершённую строку.
- Не запускайте два процесса с одним `--output` одновременно. CSV не является базой данных и не поддерживает конкурентную запись.
- Журнал находится в `logs/scraper.log`, сообщения также выводятся в терминал. Код завершения: `0` — обход завершён без ошибок загрузки, `1` — ошибка или частичный результат, `130` — остановка Ctrl+C.

Сбор сохраняет объявления как исходные наблюдения. Вероятные повторные объявления с разными ссылками обрабатываются по признакам на этапе очистки.

## Этап 3: очистка данных

### Запуск

При минимальной установке для этапа 2 добавьте зависимости обработки данных:

```powershell
.\.venv\Scripts\python.exe -m pip install pandas==2.2.3 numpy==2.2.6
.\.venv\Scripts\python.exe -X utf8 clean.py
```

По умолчанию читается скачанный файл Kaggle. Если позднее появится CSV нашего парсера, используйте `clean.py --input data/raw/listings.csv`. Все относительные пути считаются от корня проекта. Справка: `clean.py --help`.

Результаты:

- `data/processed/listings_clean.csv` — очищенные данные.
- `data/processed/listings_rejected.csv` — исключённые записи с колонкой `reason`; их можно проверить и восстановить из исходника.
- [reports/cleaning_report.json](reports/cleaning_report.json) — количество строк, причины исключения, пропуски по всем колонкам, ошибки преобразования и параметры запуска. Краткий отчёт также выводится в терминал.

Пути результатов изменяются через `--output`, `--rejected-output`, `--report`. Запись поверх входного CSV или в `data/raw` запрещена; повторный запуск с теми же параметрами обновляет результаты в `data/processed` и отчёт. Если после фильтрации не остаётся строк, существующие результаты не заменяются.

### Правила и их смысл

1. **Единая схема.** `price_local` переименовывается в `price`, `house_type` — в `building_type`, `residential_complex_name` — в `residential_complex`, `parsed_at` — в `collected_at`. Сохраняются только целевая цена, нужные признаки и служебные поля. `price_usd` и `price_per_m2` исключаются, поскольку раскрывают целевую цену. Районы Сарайшык и Сарыарка остаются разными.
2. **Числа и строки.** Поддерживаются неразрывные пробелы в разрядах, десятичная запятая, единицы площади и обозначения «тыс.», «млн», «млрд» для цены. Непонятный формат превращается в пропуск, а не в угаданное число. Текст нормализуется по Unicode, пробелам и регистру; поэтому адреса, ЖК и категории могут отображаться строчными буквами.
3. **Пропуски.** Без корректной цены или площади строка исключается. Пропуски остальных признаков сохраняются. Медианы и мода здесь не вычисляются: на этапе 5 пропуски обрабатывает пайплайн, обученный только на train. Это предотвращает использование информации из test при подготовке данных.
4. **Проверка допустимости.** Используются фиксированные широкие границы из таблицы ниже, а не квантили всей выборки. Это технические границы учебного набора, не утверждение о возможных рыночных ценах. Необычная дорогая квартира сама по себе не считается ошибкой.
5. **Дубликаты.** Сначала удаляются повторные непустые ссылки без рекламных меток. Затем сравниваются цена, все восемь признаков, адрес и ЖК. При совпадении сохраняется первая допустимая запись в исходном порядке. Для сравнения признаков должны быть известны комнаты, этаж и этажность; также требуется адрес либо заполненность всех восьми признаков. Так неполные строки не объединяются по нескольким общим значениям. Даже такое совпадение — эвристика, поэтому исключённые кандидаты сохраняются отдельно.

| Проверка | Границы включительно | Действие |
| --- | --- | --- |
| Полная цена | 1 млн — 2 млрд ₸ | Вне границ строка исключается |
| Общая площадь | 10 — 1 000 м² | Вне границ строка исключается |
| Комнаты | Целое от 1 до 20 | Ошибка заменяется пропуском |
| Этаж и этажность | Целое от 1 до 100 | Ошибка заменяется пропуском |
| Год постройки | Целое от 1850 до опорного года + 5 | Ошибка заменяется пропуском |
| Этаж выше этажности | Недопустимое противоречие | Оба значения заменяются пропусками |

Нижние границы цены и площади отсеивают грубые ошибки единиц и записи вне выбранного охвата. Верхние оставляют крупные и дорогие квартиры, но ограничивают явные ошибки порядка величины. Опорный год фиксирован: **2026**; запас до 2031 позволяет сохранить объявления строящихся домов. В исходнике есть годы 2027–2028, поэтому обрезать все будущие годы было бы неверно. Границы цены/площади настраиваются через `--min-price`, `--max-price`, `--min-area`, `--max-area`, год — через `--reference-year`; выбранные значения попадают в отчёт.

Показатель цены за м² вычисляется только временно для диагностики: записи дешевле 100 000 ₸/м² попадают в `review_candidates` отчёта и остаются в данных. Без подтверждения нельзя решить, ошибка это или особое предложение. Этот показатель не добавляется в очищенный CSV как признак.

### Как устроен пайплайн

`features.py` явно выбирает ровно восемь полей формы. Числовые: площадь, комнаты, этаж, этажность, год; категориальные: район, тип дома, состояние. URL, адрес, ЖК, дата, `source_row`, цена и цена за м² не входят в признаки. Даже лишняя колонка с ценой будет отброшена `ColumnTransformer`.

- Пропуски чисел заполняются медианами **текущей обучающей части**. Добавляются индикаторы пропусков для колонок, где они встречались на обучении. Полностью пустой числовой столбец сохраняется и заполняется нулём; индикатор показывает отсутствие информации.
- `StandardScaler` приводит числовые признаки к сопоставимому масштабу для линейной модели. Для деревьев эта же предобработка допустима.
- Пропуск категории становится значением «не указано». `OneHotEncoder` создаёт отдельные столбцы категорий без искусственного порядка. Категорий немного, а кодирование не использует цену, поэтому здесь оно проще target encoding. Неизвестная категория кодируется нулями в своём блоке; это позволяет получить прогноз, но не означает, что модель научилась оценивать новый район.
- Предобработка и регрессор находятся в одном `Pipeline`. На каждом CV-fold медианы, масштабирование и категории заново обучаются только на его тренировочной части. Сохранённый пайплайн затем выполняет эти же преобразования при прогнозе.

### Выбор модели и оценка

1. `train_test_split` отделяет 20% строк с фиксированным seed. Test не участвует в подборе. Все цены остаются в тенге, логарифмирование целевой переменной не применяется.
2. `LinearRegression`, `RandomForestRegressor` и `XGBRegressor` сравниваются на одинаковых трёх разбиениях `KFold(shuffle=True)`, сформированных **внутри train**.
3. Для семейства с минимальным средним CV MAE запускается небольшой `RandomizedSearchCV`. В лесу проверяются число деревьев, глубина, минимальный размер листа и доля признаков. Если подбор не улучшил CV MAE, остаётся исходная версия. `refit="mae"` переобучает найденный вариант на полном train; это поведение описано в [документации scikit-learn](https://scikit-learn.org/1.6/modules/generated/sklearn.model_selection.RandomizedSearchCV.html).
4. После фиксации победителя вычисляются test-метрики всех сравниваемых вариантов. Они служат итоговой диагностикой, победитель по ним заново не выбирается. Дополнительно оценивается простой ориентир — постоянный прогноз медианы цен train.
5. Сохраняется модель, обученная только на train. На полном датасете она после оценки не переобучается, поэтому test-метрики относятся именно к сохранённому пайплайну.

**MAE** — средняя абсолютная ошибка в тенге, основной критерий выбора. **RMSE** тоже измеряется в тенге, но сильнее реагирует на большие ошибки. **R²** сравнивает квадратичную ошибку с прогнозом среднего целевой переменной на оцениваемой выборке; 1 — идеальное совпадение, 0 — уровень такого константного прогноза, отрицательное значение хуже. R² не является процентом точных прогнозов.

Важность оценивается перемешиванием **исходных восьми колонок** на CV-валидации внутри train: по пять перемешиваний на fold. Чем сильнее вырос MAE после перемешивания, тем важнее признак для этой модели. Это [permutation importance](https://scikit-learn.org/stable/modules/permutation_importance.html), а не причинное влияние. Коррелирующие признаки, например площадь и комнаты, могут разделять важность. Планки на графике показывают стандартное отклонение по fold и повторам, не доверительный интервал. Гиперпараметры уже выбраны по этим CV-fold, поэтому такая важность описательная, без независимой оценки через вложенную CV; test для отбора признаков не используется.

### Ограничения оценки

Случайное разбиение январского среза проверяет похожие объявления того же периода. Оно не показывает качество на будущем рынке или новых жилых комплексах. После эвристического удаления дублей могут оставаться повторные предложения и похожие квартиры. EDA ранее рассматривала всю выборку; текущая оценка учебная, её нужно подтвердить на новом независимом срезе перед практическим применением.

В train есть объявление за 1,5 млрд ₸, а максимум test — 370 млн ₸. Такой случайный расклад дорогого хвоста помогает объяснить, почему test RMSE ниже CV RMSE. Деление не менялось и дорогие объекты не удалялись ради улучшения метрик.

Средняя ошибка не гарантирует такой же ошибки для каждой квартиры. В приложении используется `±MAE` как приблизительный ориентир вокруг прогноза: это **не 95%-интервал**, не доверительный интервал и не гарантия покрытия. На этом test 95-й процентиль абсолютной ошибки — около 26,76 млн ₸, максимальная ошибка — около 242,84 млн ₸. Дорогие объекты могут давать существенно большие ошибки. Модель прогнозирует цены предложения, а не сделки.

### Запуск

Из корня проекта, где уже установлены зависимости обучения и находятся файлы модели:

```powershell
.\.venv\Scripts\python.exe -m pip install streamlit==1.45.1
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Откройте [локальное приложение](http://127.0.0.1:8501). Терминал должен оставаться запущенным; **Ctrl+C** останавливает сервер. На Linux/macOS замените путь к Python на `.venv/bin/python`. Если порт занят, добавьте `--server.port 8502` и используйте адрес с этим портом.

Конфигурация `.streamlit/config.toml` задаёт светлую тему и адрес `127.0.0.1`: приложение доступно на текущем компьютере. Повторное обучение при запуске страницы не выполняется. Для прогноза достаточно двух артефактов из одного запуска этапа 5: `models/best_model.joblib` и `models/model_metadata.json`; исходный CSV не нужен.

### Использование

1. Заполните площадь и количество комнат, выберите район, тип дома и состояние. Укажите этаж, этажность и год постройки, если они известны. Числовые поля изначально пусты; примеры в подсказках не подставляются в модель.
2. Нажмите **«Рассчитать стоимость»**. Цена за м² вычисляется делением прогноза полной цены на введённую площадь.
3. Под ценой показан диапазон `max(0, прогноз − MAE) … прогноз + MAE`, где MAE берётся из описания сохранённой модели. Это приблизительный ориентир без гарантии покрытия.
4. После изменения параметров нажмите кнопку снова. Раздел «Параметры этого расчёта» хранит именно отправленные значения, чтобы результат не путался с ещё не отправленными изменениями формы.

Форма поясняет, что это цена **предложения**, а не сделки, и что модель обучена на объявлениях января 2026 года. Утверждение о периоде относится к текущему датасету; при обучении на другом источнике его нужно актуализировать вместе с описанием проекта.

### Проверки и обработка ошибок

`prediction.py` проверяет диапазоны этапа очистки, целочисленность комнат/этажей/года и условие «этаж ≤ этажность». Пустые площадь и комнаты не допускаются. Неизвестные остальные параметры передаются как `NaN`, их обрабатывает обученный пайплайн. Значение за пределами наблюдавшегося диапазона train вызывает предупреждение, даже если находится в широких допустимых границах.

Модель кэшируется между расчётами. При изменении размера или времени изменения любого из двух файлов кэш обновляется; при загрузке проверяются схема входных признаков и SHA256 модели. Приложение не принимает загружаемые пользователем joblib-файлы — используется только собственный локальный артефакт проекта. Ошибки загрузки, некорректный ввод и неположительные/неконечные прогнозы показываются понятным сообщением. При неудачном новом расчёте старый результат убирается.

Автономные проверки, включая форму через Streamlit AppTest:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -p test_app.py -v
```

Проверены реальная сохранённая модель, формулы цены за м² и диапазона, неверные значения, пустые поля, очистка ранее заполненных полей, повреждённые артефакты и отсутствие устаревшего прогноза после ошибки. Интеграционные тесты с моделью пропускаются, если её артефакты ещё не созданы. Форма также проверена в браузере на локальном сервере.

В финализации проверены справки CLI, соответствие зависимостей окружению, локальные ссылки документации и сохранённые метрики. Новое обучение ради документации не выполнялось.

## Если что-то не запускается

| Симптом | Что проверить |
| --- | --- |
| `python` или `py` не найдены | В существующем проекте используйте `.venv\Scripts\python.exe`; на новом компьютере установите Python 3.12 |
| `ModuleNotFoundError` | Запускайте Python из `.venv` и установите полный набор зависимостей по инструкции выше |
| Нет исходного CSV | Восстановите закреплённую версию Kaggle по [data/SOURCES.md](data/SOURCES.md) |
| CSV не совпадает с отчётом очистки | Повторите `clean.py`, затем нужный этап; не редактируйте SHA256 вручную для обхода проверки |
| Файлы модели отсутствуют или не совпадают | Выполните `train.py` либо восстановите joblib и JSON **одного** запуска |
| Ошибка версии при загрузке joblib | Сверьте Python/ML-библиотеки с `model_metadata.json` или переобучите модель в новом окружении |
| `127.0.0.1:8501` недоступен | Запустите сервер командой Streamlit и оставьте терминал открытым; сам открытый браузер сервер не запускает |
| Порт 8501 занят | Добавьте `--server.port 8502` к команде запуска и откройте `http://127.0.0.1:8502` |
| Парсер получает 403/429 или CAPTCHA | Остановите сбор, проверьте разрешение и правила сайта; автоматический обход не предусмотрен |

## Ограничения модели

| Ограничение | Практическое следствие |
| --- | --- |
| Объявления января 2026 года | Модель не учитывает последующие изменения рынка; это не текущая оценка стоимости |
| Цены предложения | Реальная цена сделки и торг неизвестны |
| Случайный split одного среза | Метрики не подтверждают качество на будущих датах и ранее не встречавшихся зданиях |
| Вероятные повторные предложения | Эвристическая очистка не доказывает уникальность квартир; сходные объекты могут оказаться в train и test |
| Нет точной географии и характеристик ЖК во входах | Район слишком грубо описывает местоположение; вид, инфраструктура, застройщик и другие детали не учтены |
| Состояние отсутствует у 58,55% очищенных строк | Влияние ремонта изучено по неполным сведениям; заполнение пропусков не восстанавливает факты |
| Редкие дорогие квартиры и необычные сочетания параметров | Средние метрики скрывают крупные ошибки; допустимое значение поля не гарантирует достоверный прогноз |
| Диапазон ±MAE | Для всех квартир используется одна и та же MAE; покрытие не гарантировано |

Две записи с необычно низкой ценой за м² оставлены для ручной проверки, поскольку достоверной причины исключения нет. Предварительную обработку автором исходного датасета нельзя полностью восстановить. EDA рассматривала всю выборку до обучения; перед практическим применением потребуется новый независимый контрольный набор.

## Идеи улучшения

Приоритет — улучшить проверку и данные, затем усложнять модель:

1. **Свежие снимки рынка и временной тест.** Получить новые данные из разрешённого источника, обучаться на более ранних датах и оценивать на более поздних. Учитывать изменение цен и повторные публикации одной квартиры.
2. **Групповое разбиение.** Сопоставить адреса и идентификаторы объектов, разделять train/test по квартирам или зданиям. Это поможет проверить, насколько метрики зависят от похожих объектов в обеих частях.
3. **Проверка ошибок по сегментам.** Считать MAE отдельно по районам, ценовым диапазонам, площади и новостройкам/вторичке; исследовать крупные ошибки и подозрительные исходные записи.
4. **Более точные признаки.** Добавить проверенные координаты, ЖК, застройщика, дату объявления и доступные характеристики дома; эти поля должны быть известны и при прогнозе. Не добавлять вычисленную из целевой цены стоимость за м².
5. **Интервалы с проверяемым покрытием.** Исследовать квантильные модели или conformal prediction с отдельной калибровочной выборкой; проверить покрытие и ширину по сегментам вместо обещания точности через ±MAE.
6. **Новые эксперименты внутри train.** Сравнить логарифмирование цены, устойчивые функции потерь и расширенный подбор параметров. Преобразования обучать внутри CV; финальные изменения оценивать на новом test, чтобы не подгоняться к уже просмотренному.
7. **Развитие приложения.** При необходимости добавить FastAPI с той же функцией `predict_apartment`, контроль версии модели и отдельный план размещения сервиса. Текущая реализация запускается локально на Streamlit.

Эти улучшения предложены как дальнейшая работа и не входят в завершённую учебную версию.
